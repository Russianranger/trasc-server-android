# 0.4.2: playback, NPC comparison and launcher controls

User now finds FPS and loading acceptable on the Thor. The 10.59-second September 15 19:31 video shows Guard Sunblaze's hair and exposed skin switching between textured and flat-colored surfaces while the surrounding scene stays stable. The current game log reports a failed `RenderEffects/SPL/SkinMeshCBS1_VSB.fxo` effect, but other skin techniques load. That failure alone does not establish the cause of this NPC flicker. No missing game asset is replaced or fabricated.

The uploaded Wine log loads native libasound, then fails to open Linux ALSA devices. There was no Android playback endpoint. The app now owns a private Unix socket and AudioTrack sink for the client lifetime. A small APK-bundled ARM64 glibc ALSA ioplug connects Wine's existing native-wrapped ALSA library to that sink. ALSA's built-in plug converts input to 48 kHz stereo signed 16-bit PCM. The actual AudioTrack playback head supplies progress, and nonblocking Android writes report exactly the accepted frames. No unpaced null device, microphone permission or TCP audio listener is used. Audio focus controls playback volume. Closing a client, failed startup, or process exit closes sockets and tracks. Playback is independent of the game display activity so Back/Return does not destroy sound.

The protocol is little endian: initial words `0x50414c54,1,48000,2,buffer_frames`, then one-word commands Start=1, Stop=2, Position=3, Write=4 plus frame count and PCM, Reset=5. Responses are one word: status, played-frame counter, or accepted frames. Limits: eight same-UID connections, 64–48000 buffer frames, 4096 frames per message, one-second native socket deadlines, bounded drain, 256 KiB diagnostics. Android accepts the existing runtime without a download. The bundle hash and ARM64 identity are checked before Wine. `client-audio.log` and its previous copy record focus, volume, errors, frames and nonzero samples, never microphone or raw audio. Old MIDI synthesis is not implemented; the existing missing software synthesizer message may remain. Wave/DirectSound audio and MIDI are separate capabilities.

NPC compatibility is a reversible Turnip option, enabled for this comparison. It uses pinned DXVK 2.5.3's `d3d9.floatEmulation=Strict`, `d3d9.forceSamplerTypeSpecConstants=True` and `d3d9.allowDirectBufferMapping=False`; EverQuest's existing cached-dynamic-buffer profile remains active. These address legacy math, shader/texture type agreement and unsafe buffer updates. They are a targeted compatibility trial, **not a confirmed fix for Guard Sunblaze**. Standard restores 0.4.1's configuration. The shader named in the game error is checked for presence, size and checksum in session state; its bytes are not exported. Keep the same NPC/route and compare both modes at 720p before changing other settings.

Runtime Start/Stop and status now occupy a sticky bar above all tabs. These control the server runtime and database, preserving the existing clean shutdown operation. Client Stop remains separate. The launcher uses a fantasy gold TL monogram, with adaptive icon insets for circular masks. The footer now reports 0.4.2/code19.

Validation gates: existing backend/JVM/browser/Android and graphics suites; real native ALSA conversion and playback timing with a bounded real-time test sink; real 32-bit Windows waveOut and DirectSound through Wine/Box64, both direct and PRoot, with nonzero stereo samples; complete stop/relaunch playback; strict original exit and shader/model/framebuffer checks. The JVM protocol test checks partial writes, endian/PCM correctness, playback-head replies, malformed/truncated input, limits and sink cleanup. CI has no physical Android speaker or Adreno device: audible output and NPC appearance require the Thor acceptance test. Local sandbox blocks Unix socket creation, so native playback is tested on the ARM64 CI runner; local Java compilation and protocol tests still run.
